# Debugging

This page is a runbook for the failures contributors hit most often in Strata: build gates that reject a change, configuration that does not load, and calculations that return failures instead of values. Each section gives the symptom, the cause and the fix, followed by notes on logging.

## Build failures

| Symptom | Cause | Fix |
| --- | --- | --- |
| Build stops in `process-sources` with `maven-checkstyle-plugin` errors naming a file, line and rule | A style rule from the OpenGamma `build-config` 2.8.1 ruleset is violated (indentation, import order, Javadoc, whitespace) | Fix the source to match neighbouring code. Do not skip or relax the check. Re-run the same focused `mvn -pl ... -am test` command. CI skips Checkstyle only in the test step because the install step already ran it |
| Under `-Dstrict`, `joda-beans-maven-plugin:validate` fails at `validate` and names a bean class | The code between `AUTOGENERATED START` and `AUTOGENERATED END` does not match what the generator would write, because a property changed without regenerating, or the block was edited by hand | Regenerate with the IDE plugin or `mvn -pl <module> org.joda:joda-beans-maven-plugin:generate`, then review the diff. Never edit inside the markers. Scala beans in `collect` and `basics` are not checked by this plugin, so mistakes there show up as `TestHelper.coverImmutableBean` failures instead |
| `spotless-maven-plugin` fails at `validate` in a linked worktree or a copy without `.git`, complaining about the git repository or the `main` ref | `ratchetFrom main` needs a normal checkout with a `main` branch to compute changed files | Add `-Dspotless.check.skip=true`. In a normal clone, make sure a local `main` branch exists |
| Spotless reports formatting violations in files you changed | Changed Java files do not match `eclipse/install/Strata-Eclipse-Formatter-Java.xml` | Run `mvn spotless:apply` on the module or reformat in the IDE, then review the diff |
| `python3 config/pmd/check-pmd-baseline.py` prints `New complexity finding`, `Complexity increased from X to Y` or `New dead-code finding` | A method now exceeds the cyclomatic complexity threshold, got more complex, or has an unused private field, method or assignment that is not in `config/pmd/pmd-baseline.json` | Simplify the method or remove the dead code. Only if the finding is acceptable, regenerate with `--update-baseline` and commit the reviewed JSON. `Missing PMD report` means the build did not run `process-sources` for every module; run a full `mvn test` (or `install`) first |
| `forbiddenapis` fails `check` or `testCheck` with a forbidden method or class | The code uses an API in the `jdk-unsafe`, `jdk-deprecated` or `jdk-non-portable` signature sets: default-locale `String.format` or `toLowerCase()`, default-charset readers, `sun.*` or `com.sun.*` classes | Pass an explicit `Locale` or `Charset`, or use a portable API. Commit `d9c689c` is an example: `FailureItem.scala` read `-XX:MaxJavaStackTraceDepth` through `com.sun.management.HotSpotDiagnosticMXBean`, which `jdk-non-portable` bans, so it now assumes the JVM default depth of 1024 |
| `cannot find symbol` for a JDK method such as `List.of`, `Optional.isEmpty` or `String.strip` in a Java module | Java modules compile with `maven.compiler.release` 8 (profile `forcejavaversion` in `modules/pom.xml`), so post-Java-8 APIs are not visible | Use a Java 8 equivalent or a Guava/`Guavate` helper, for example `ImmutableList.of` |
| Enforcer failure under `-Dstrict` about banned or duplicate dependencies, or a missing plugin version | `maven-enforcer-plugin` bans `commons-logging`, `org.json:json` and non-test `junit:*`, rejects duplicate classes, and requires explicit plugin versions | Remove or exclude the dependency; give the plugin a literal version. Commit `703ffe9` pinned the `scala-maven-plugin` version literally for this reason |
| `OutOfMemoryError` or a forked test JVM killed in CI or in a container | The JVM sizes its heap from host memory, not the container limit, and two forked test JVMs plus Maven exceed it | Set `JAVA_TOOL_OPTIONS=-XX:MaxRAM=3572m` and `MAVEN_OPTS=-Xmx1g` as `.circleci/config.yml` does, and run tests with `-T 1` |
| A test fails once and passes on retry, and the build continues | `rerunFailingTestsCount` 1 in `modules/pom.xml` retries failing tests | Look for the flaky entry in `target/surefire-reports/*.xml` and fix the test; shared static state between test classes is a common cause |

## Scala module problems (`collect` and `basics`)

| Symptom | Cause | Fix |
| --- | --- | --- |
| A downstream Java module fails to compile against `collect` or `basics`, or tests see old behavior | Maven picked up `strata-collect` or `strata-basics` jars from `~/.m2` instead of the current reactor output | Build with `-am` or include `modules/collect,modules/basics` in `-pl`. Run `mvn clean` on the Scala modules if the incremental compile looks stale |
| Odd results after editing Scala sources, such as missing `@SafeVarargs` warnings or `IOException` mismatches | `scala-maven-plugin` 4.10.0 compiles in `Mixed` order at `process-resources`, then the antrun restorers rewrite class files at `process-classes`. Mixing an IDE build with a Maven build can leave unrestored classes in `target/classes` | Run `mvn -pl modules/collect clean install` so compile and restore run in order. The restorer controls in `modules/collect/src/build/test` fail the `test` phase if restoration did not happen |
| `RestoreSafeVarargsControls` or `RestoreBridgeExceptionsControls` fails | A change to `Guavate` or `ArrayByteSource` altered the method descriptors that `RestoreSafeVarargs` or `RestoreBridgeExceptions` target | Update the target list in `modules/collect/src/build/java/RestoreSafeVarargs.java` or `RestoreBridgeExceptions.java` and the matching controls, keeping the Java-facing descriptors unchanged |
| The build helpers fail to compile on JDK 21 with a warning about obsolete source or target 8 turned into an error | They compile with `release="8"`, `-Xlint:all` and `-Werror`, and JDK 21 warns that release 8 is obsolete | Already fixed by commit `7caa43e`, which adds `-Xlint:-options` in `modules/collect/pom.xml`. Keep that flag if you change the helper compile |
| Scaladoc generation under `-Ddist` fails with a Jackson class error | Scaladoc 3.9.0 resolves an older `jackson-annotations` that lacks `JsonSerializeAs` | `modules/collect/pom.xml` and `modules/basics/pom.xml` add `jackson-annotations` 2.21 as an `additionalDependency`; keep it |
| A Java caller gets `NoSuchMethodError` or `AbstractMethodError` against a Scala class | The Scala change altered a binary detail: a static forwarder, a getter name, a trait forwarder, or a checked exception | Compare against `main` with `javap -p -s` on the class. The rules are on [Scala and Java interoperability](../features/scala-java-interop.md) |
| `FailureItem` stack traces contain unexpected frames, or `FailureItemTest` fails | `FailureItem.scala` filters Scala varargs and static forwarder frames and applies a 1024-frame limit | See commits `2cd7a97`, `7137a16`, `7ca24cb` and `d9c689c` and the comments around `isForwarderFrame` in `modules/collect/src/main/scala/com/opengamma/strata/collect/result/FailureItem.scala` |

## Configuration and reference data

| Symptom | Cause | Fix |
| --- | --- | --- |
| `IllegalArgumentException: DayCount name not found: XYZ` (or `HolidayCalendarId`, `IborIndex` and so on) | The name is not registered in any INI file for that `ExtendedEnum`, or the whole enum failed to load | Check the INI file under `modules/basics/src/main/resources/META-INF/com/opengamma/strata/config/base/` (for example `DayCount.ini`) and any `library` or `application` overrides. Look for a SEVERE log line `Failed to load ExtendedEnum for ...`: when loading fails, `ExtendedEnum.of` logs the stack trace and returns an empty enum to avoid `ExceptionInInitializerError`, so every later lookup reports "name not found" |
| `IllegalStateException: No files found on the classpath: [...]` or `More than one file found on the classpath: ...`, with a matching SEVERE log line | `ResourceConfig` found the named file in no configuration directory, or found copies with different content in the same directory (identical copies, as when Strata is on the classpath twice, are accepted) | Fix the classpath, or move your file to a directory of its own such as `application` |
| A WARNING `Invalid system property directory, must match regex [A-Za-z0-9-]+` | The `com.opengamma.strata.config.directories` system property has an invalid entry | Use comma-separated names of letters, digits and hyphens, for example `-Dcom.opengamma.strata.config.directories=base,library,application,user` |
| Custom holidays or indices are ignored | The override is in a directory with lower priority, or in a directory not listed in `com.opengamma.strata.config.directories` | Directories are searched from `base` to `application`, later ones taking priority. Turn on CONFIG logging for `ResourceConfig` (below) to see `Using directories: ...` and `Resources found: ...` |
| `ReferenceDataNotFoundException` when resolving a trade | The `ReferenceData` passed to `resolve` lacks an id, typically a holiday calendar or security | Use `ReferenceData.standard()` or combine it with your own data. The class is `modules/basics/src/main/scala/com/opengamma/strata/basics/ReferenceDataNotFoundException.scala` |

[Reference data and configuration](../features/reference-data-and-configuration.md) describes the directory search in detail.

## Market data and calculation results

| Symptom | Cause | Fix |
| --- | --- | --- |
| `MarketDataNotFoundException: Market data not found for '...' of type '...'` | A pricer or function asked `MarketData.getValue` for an id that was not supplied, often a quote, FX rate or curve with a slightly different name | Compare the id in the message to the ids in your `MarketData`. The exception is `modules/data/src/main/java/com/opengamma/strata/data/MarketDataNotFoundException.java`, a subclass of `IllegalArgumentException` |
| A report cell is empty or shows an error, but no exception is thrown | The calculation engine returns `Result` failures per cell instead of throwing | Inspect the cell (below) |
| `IllegalStateException` from `Result.getValue()` | The code read the value of a failed `Result` | Check `isSuccess()` or `isFailure()` first, or use `getValueOrElse` |

### Reading failures from `Results`

`Results` (`modules/calc/src/main/java/com/opengamma/strata/calc/Results.java`) is a grid of `Result` cells, one row per target (trade) and one column per `Column`. To find out why a cell failed:

```java
Result<?> cell = results.get(row, column);
if (cell.isFailure()) {
  Failure failure = cell.getFailure();
  System.out.println(failure.getReason() + ": " + failure.getMessage());
  for (FailureItem item : failure.getItems()) {
    System.out.println(item.getReason() + " " + item.getMessage());
    System.out.println(item.getStackTrace());
  }
}
```

The `FailureReason` values in `modules/collect/src/main/scala/com/opengamma/strata/collect/result/FailureReason.scala` give a first hint: `MISSING_DATA` points at market data, `CURRENCY_CONVERSION` at a missing FX rate, `NOT_APPLICABLE` at a measure the function does not support for that trade, `CALCULATION_FAILED` or `ERROR` at an exception inside the pricer (see the item's stack trace), and `MULTIPLE` when several items were combined. Loaders return `ValueWithFailures`, whose `getFailures()` lists rows that could not be parsed.

## Logging

Strata uses two logging APIs:

- **`java.util.logging`** in about 33 files, including the configuration path in the Scala modules: `ExtendedEnum.scala` (FINE on each load, SEVERE on failure), `ResourceConfig.scala` (CONFIG for directories and files used, WARNING for a bad system property, SEVERE for missing or duplicate files) and `HolidayCalendarIniLookup.scala` (SEVERE for bad holiday INI files).
- **SLF4J** (`slf4j-api` 1.7.36) in about 23 files, mostly in `modules/math` and `modules/pricer` numerical code, and `ListenerWrapper` in `modules/calc`, which logs exceptions thrown by calculation listeners. The library declares no binding; `modules/math` uses `slf4j-nop` in tests and `examples` uses `slf4j-simple`.

To see the configuration messages, which are below the default INFO level, create a `logging.properties` file:

```properties
handlers=java.util.logging.ConsoleHandler
java.util.logging.ConsoleHandler.level=FINE
com.opengamma.strata.collect.io.ResourceConfig.level=CONFIG
com.opengamma.strata.collect.named.ExtendedEnum.level=FINE
```

and pass `-Djava.util.logging.config.file=/path/to/logging.properties` to the JVM, for example through `JAVA_TOOL_OPTIONS` so that forked test JVMs pick it up. For SLF4J output in the examples, `slf4j-simple` reads `-Dorg.slf4j.simpleLogger.defaultLogLevel=debug`.

CI adds `-DtrimStackTrace=false` to `.mvn/maven.config`, so Surefire reports keep full stack traces. Do the same locally when a test failure ends in a truncated trace.
