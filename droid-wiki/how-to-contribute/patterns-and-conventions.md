# Patterns and conventions

Strata code follows a small set of patterns that repeat across all eleven modules: immutable value types, Joda-Beans for bean metadata, static factories with `ArgChecker` validation, extensible named types loaded from configuration, and `Result` objects instead of exceptions inside the calculation engine. This page describes each pattern, points to a reference implementation, and lists the style rules the build enforces.

The repository's own agent guidance in `.factory/skills/code-conventions/SKILL.md` and `AGENTS.md` covers the same ground in checklist form. This page explains the reasoning and shows where to look.

## Immutable value types

Almost every public type in Strata is immutable and thread-safe. Class Javadoc usually ends with the line "This class is immutable and thread-safe." Operations such as `plus`, `multipliedBy` or `withAmount` return new instances.

There are two ways to write such a type.

### Plain immutable class

Small value types with hand-written behavior use a plain final class. The reference is `CurrencyAmount` in `modules/basics/src/main/scala/com/opengamma/strata/basics/currency/CurrencyAmount.scala`:

- final class, private constructor, `Serializable` with serial version UID 1
- static factories (`of`, `zero`, `parse`) instead of public constructors
- `parse(String)` annotated with Joda-Convert `@FromString`, and `toString()` annotated with `@ToString`, so the type round-trips through strings
- hand-written `equals`, `hashCode`, and `compareTo` built with Guava `ComparisonChain`

On this branch the `basics` and `collect` versions are Scala, so the shape is written with Scala syntax:

```scala
@SerialVersionUID(1L)
final class CurrencyAmount private (rawCurrency: Currency, rawAmount: Double)
  extends FxConvertible[CurrencyAmount] with Comparable[CurrencyAmount] with Serializable {

  private val currency: Currency = ArgChecker.notNull(rawCurrency, "currency")
  private val amount: Double = ArgChecker.notNaN(rawAmount + 0d, "amount")  // this weird addition removes negative zero
  ...
```

Java modules use the same structure in Java. See [Scala and Java interoperability](../features/scala-java-interop.md) for how the Scala classes keep Java-style getters and static methods.

### Joda-Beans immutable bean

Types that benefit from property metadata, builders and generic serialization are Joda-Beans. Strata uses this for trades, products, conventions, curve definitions and most configuration-like objects. About 560 Java files and 59 Scala files contain generated bean code.

The light-bean reference is `QuoteId` in `modules/market/src/main/java/com/opengamma/strata/market/observable/QuoteId.java`:

```java
@BeanDefinition(style = "light", cacheHashCode = true)
public final class QuoteId
    implements ObservableId, ImmutableBean, Serializable {

  @PropertyDefinition(validate = "notNull", overrideGet = true)
  private final StandardId standardId;
  ...
  public static QuoteId of(StandardId standardId) { ... }

  //------------------------- AUTOGENERATED START -------------------------
  ...
  //-------------------------- AUTOGENERATED END --------------------------
}
```

Rules for beans:

- Declare properties as `private final` fields annotated with `@PropertyDefinition`. Common options are `validate = "notNull"`, `validate = "ArgChecker.notNegative"`, `overrideGet = true` and `get = "optional"`.
- The Joda-Beans code generator writes the meta-bean, getters, builder, `equals`, `hashCode` and `toString` between the `AUTOGENERATED START` and `AUTOGENERATED END` markers. Do not edit inside the markers. Regenerate instead, with the Joda-Beans IDE plugin or the `joda-beans-maven-plugin` `generate` goal.
- The `strict` profile in `modules/pom.xml` (activated by `-Dstrict`, as CI does) binds the `joda-beans-maven-plugin` `validate` goal to the `validate` phase with `stopOnError`, so a Java bean whose generated block is stale fails a strict build. A plain `mvn install` does not run this check.
- Validation that spans several properties goes in a method annotated `@ImmutableValidator`; defaults go in `@ImmutableDefaults`; normalization before validation goes in `@ImmutablePreBuild`. Around 270 Java files use one of these hooks.

The generator only reads Java source. In the Scala modules the code inside the markers was translated from the generated Java during the migration and is maintained by hand. An example is `modules/basics/src/main/scala/com/opengamma/strata/basics/ImmutableReferenceData.scala`, which uses `@(PropertyDefinition @field)` so the annotation lands on the field as the generator expects. If you add or change a property on a Scala bean, update the meta-bean code to match what the generator would produce for the Java equivalent, and run the bean tests.

## Static factories and validation

Constructors are private. Callers use static factories:

- `of(...)` for construction from parts, for example `CurrencyAmount.of(Currency.GBP, 12.34)`
- `parse(String)` for string forms, paired with `@FromString`
- `builder()` for Joda-Beans with many properties
- `standard()`, `empty()`, `minimal()` for well-known instances, as on `ReferenceData` in `modules/basics/src/main/scala/com/opengamma/strata/basics/ReferenceData.scala`

Public arguments are checked with `ArgChecker` (`modules/collect/src/main/scala/com/opengamma/strata/collect/ArgChecker.scala`): `notNull`, `notEmpty`, `notBlank`, `notNaN`, `notNegative`, `notNegativeOrZero`, `inRange`, `isTrue` and others. They throw `IllegalArgumentException` with a formatted message, and factory Javadoc documents that exception.

Messages use `Messages.format` (`modules/collect/src/main/scala/com/opengamma/strata/collect/Messages.scala`), which substitutes `{}` placeholders. `modules/product/src/main/java/com/opengamma/strata/product/SecurityPosition.java` uses it to build a `ClassCastException` message, for instance. A typical call looks like this:

```java
throw new IllegalArgumentException(Messages.format("Unknown index: {}", name));
```

## Named and extensible types

Many domain concepts are a fixed-looking set of values that users can extend: currencies, day counts, holiday calendars, IBOR and overnight indices, roll conventions, trade conventions. Strata models these with types from `modules/collect/src/main/scala/com/opengamma/strata/collect/named/`:

| Type | Role |
| --- | --- |
| `Named` | A type with a unique `getName()`, round-tripped by `of(String)` |
| `ExtendedEnum` | A registry of `Named` instances loaded from INI configuration, with alternate names and external name groups |
| `CombinedExtendedEnum` | Merges several extended enums behind one lookup |
| `NamedEnum`, `EnumNames` | Real enums that need lenient name parsing and formatting |

`DayCount` is a typical extended enum: `modules/basics/src/main/scala/com/opengamma/strata/basics/date/DayCounts.scala` holds the lookup `ExtendedEnum.of(classOf[DayCount])`. When it is first used, the registry reads `modules/basics/src/main/resources/META-INF/com/opengamma/strata/config/base/DayCount.ini`, which names the provider classes and their constant fields. Applications can add values by placing their own INI file in the `library` or `application` configuration directories. [Reference data and configuration](../features/reference-data-and-configuration.md) explains the directory search order and the `com.opengamma.strata.config.directories` system property.

Identifiers follow the same idea. `StandardId` (scheme plus value) identifies securities, legal entities and quotes, and typed ids such as `HolidayCalendarId` or `QuoteId` wrap it.

## Resolve before pricing

Products and trades that depend on reference data implement `Resolvable`. Calling `resolve(ReferenceData)` turns, for example, a `Swap` into a `ResolvedSwap` with concrete payment dates, holiday-adjusted schedules and fixed indices. Pricers in `modules/pricer` only accept resolved types. This keeps date logic out of pricing code and lets a resolved trade be priced many times (for scenarios) without re-resolving. See [Pricing a trade](../features/pricing-a-trade.md).

## Results instead of exceptions in the engine

The calculation engine runs many trades and measures at once and should not stop at the first bad trade. Code in `modules/calc` and `modules/measure` returns `Result<T>` values (`modules/collect/src/main/scala/com/opengamma/strata/collect/result/Result.scala`):

- `Result.success(value)` for a value
- `Result.failure(FailureReason, message, args...)` for an expected failure, such as missing market data
- `Result.of(supplier)` to run code and capture any exception as a failure

A `Failure` holds one or more `FailureItem`s, each with a `FailureReason`, message, and optional cause and stack trace. Calculation functions such as `modules/measure/src/main/java/com/opengamma/strata/measure/swap/SwapTradeCalculationFunction.java` wrap per-measure work this way, and `Results` in `modules/calc` exposes a grid of `Result` cells. Loaders use the related `ValueWithFailures` to return parsed rows together with the rows that failed.

Outside the engine, normal exceptions are fine: `IllegalArgumentException` for bad input, `ParseFailureException` for parse errors, and `MarketDataNotFoundException` (`modules/data/src/main/java/com/opengamma/strata/data/MarketDataNotFoundException.java`) for missing market data.

## Collections and streams

- Public APIs return Guava immutable collections (`ImmutableList`, `ImmutableMap`, `ImmutableSet`).
- `Guavate` (`modules/collect/src/main/scala/com/opengamma/strata/collect/Guavate.scala`) supplies collectors such as `toImmutableList()` and `toImmutableMap(...)`, plus stream helpers like `zipWithIndex` and `stream(Optional)`.
- Numeric data uses the primitive arrays in `modules/collect/src/main/scala/com/opengamma/strata/collect/array/` (`DoubleArray`, `DoubleMatrix`, `IntArray`) instead of `List<Double>`.
- Time series use `LocalDateDoubleTimeSeries` from `modules/collect/src/main/scala/com/opengamma/strata/collect/timeseries/`.

## Public API and `impl` packages

The public API is kept backwards compatible. New public types and methods need complete Javadoc and should follow existing names (`of`, `parse`, `builder`, `getX`, `withX`, `toX`).

Packages named `impl` are excluded from that promise. `modules/pricer/src/main/java/com/opengamma/strata/pricer/impl/package-info.java` states that code there "may change in a non-backwards compatible way". The same applies to `modules/math/src/main/java/com/opengamma/strata/math/impl` and `modules/loader/src/main/java/com/opengamma/strata/loader/impl`. Do not expose `impl` classes through another module's API.

For `collect` and `basics`, the Java-facing API also includes binary details: class and member names, method descriptors, static entry points, checked exceptions and Joda-Beans metadata. Scala changes must keep those identical. [Scala migration](../background/scala-migration.md) records the techniques used (`@static` companion methods, `-Xmixin-force-forwarders:false`, bytecode restorers in `modules/collect/src/build`).

## Code style

| Rule | Enforced by |
| --- | --- |
| Two-space indentation, no tabs | Checkstyle 8.45.1 with the OpenGamma `build-config` 2.8.1 rules (configured in `modules/pom.xml`); Eclipse formatter `eclipse/install/Strata-Eclipse-Formatter-Java.xml` |
| Import grouping and order | Checkstyle, Spotless (`ratchetFrom main`) |
| Section separators `//-------------------------------------------------------------------------` between groups of methods | Convention |
| Javadoc on every public class and method, paragraphs separated with `<p>` | Checkstyle, plus the Javadoc build under `-Ddist` |
| No unsafe, deprecated or non-portable JDK APIs (default locale, default charset and similar) | forbiddenapis with the `jdk-unsafe`, `jdk-deprecated` and `jdk-non-portable` signatures |
| No new PMD findings beyond the baseline | `config/pmd/check-pmd-baseline.py` with `config/pmd/pmd-baseline.json` |
| Java modules compile against Java 8 APIs | `maven.compiler.release` 8 in `modules/pom.xml` |

Scala files in `collect` and `basics` keep the same two-space indentation, copyright header, section separators and ScalaDoc density as the Java they replaced. ScalaDoc is published as the javadoc jar for those modules.

## Tests

Tests are JUnit 5 with AssertJ and live in `src/test/java` of each module, one test class per production class in the same package (`CurrencyAmount` has `CurrencyAmountTest`). Tests for the Scala modules are still Java, which exercises the Java-facing API directly.

`TestHelper` (`modules/collect/src/test/java/com/opengamma/strata/collect/TestHelper.java`) is used across modules:

| Helper | Use |
| --- | --- |
| `coverImmutableBean(bean)` | Exercises meta-bean, builder and property code of a Joda-Bean (called in about 550 test files) |
| `coverBeanEquals(bean1, bean2)` | Checks `equals` and `hashCode` of two different beans |
| `assertSerialization(obj)` | Java serialization round trip |
| `assertJodaConvert(Class, obj)` | `@FromString`/`@ToString` round trip |
| `assertJodaSerialization(bean, id)` | Joda-Beans XML/JSON round trip |
| `assertUtilityClass(Class)` | Checks a final class with a private constructor and only static methods |
| `coverPrivateConstructor`, `coverEnum` | Coverage helpers |
| `date(y, m, d)`, `list(...)` | Compact fixtures |

See [Testing](testing.md) for how to run tests and the test layout of each module.
