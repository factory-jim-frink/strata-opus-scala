# Strata build and test

Strata is a multi-module Maven reactor: eleven library modules under `modules/`
plus `examples/`. The modules build together as one unit and are not deployed
separately.

## Prerequisites

- Java 17 or later. The Java modules compile with `--release 8`; the `collect` and `basics`
  modules are Scala 3.9.0 LTS (JDK 17+ required) and are compiled by `scala-maven-plugin`.
  CircleCI builds on Java 17 and 21.
- Maven 3.5 or later. There is no Maven wrapper; use a system `mvn`.

## Full build

From the repository root:

```sh
mvn install
```

This compiles every module, runs the Checkstyle check, validates the Joda-Beans
generated code, and runs all tests. `mvn test` runs the same tests without the
install phase.

## Focused test run

To run a single test class, first find its module (a directory under `modules/`,
or `examples/`), then build just that module and its dependencies:

```sh
mvn -pl modules/basics -am -Dtest=CurrencyAmountTest -Dsurefire.failIfNoSpecifiedTests=false test
```

- `-pl` selects the module containing the test.
- `-am` also builds the modules it depends on, in reactor order.
- `-Dsurefire.failIfNoSpecifiedTests=false` stops upstream modules from failing
  just because the named test class does not exist there.
- Keep `-am` (or list `modules/collect` too) when building `basics` or a
  downstream module, so the reactor uses the current Scala `collect`/`basics`
  classes rather than older jars from `~/.m2`.
- In a linked git worktree, add `-Dspotless.check.skip=true`; the Spotless
  `ratchetFrom main` check needs a normal checkout.

The same pattern works for the `examples` module:

```sh
mvn -pl examples -am -Dtest=FxPricingIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false test
```

## Module map

Use this map to pick the right `-pl` target and to reason about which modules a
change affects. Dependencies flow roughly from top to bottom.

| Module | Contents |
| --- | --- |
| `collect` | shared foundations: `ArgChecker`, tuples, Guava helpers, messages (Scala 3.9.0) |
| `basics` | foundational finance types: dates, day counts, currency, indices, conventions (Scala 3.9.0) |
| `data` | domain data model: market data identifiers and observables |
| `math` | mathematical models: integration, differentiation, root finding, matrices |
| `market` | market data models: curves, surfaces, volatilities, shifts |
| `product` | financial products: trades, swaps, rates, credit |
| `pricer` | pricing functions and measures per product |
| `calc` | calculation engine: runner, columns, market data rules |
| `measure` | combines `pricer` and `calc` into the published calculation API |
| `loader` | CSV and FpML input loaders |
| `report` | formats calculation results as trade and cash flow reports |
| `examples` | runnable end-to-end examples composing the library |

## Checkstyle

The build runs `maven-checkstyle-plugin` at the `process-sources` phase with
`failsOnError=true`, so a style violation fails the build before compilation.
The ruleset comes from the OpenGamma `build-config` artifact; it is not stored in
this repository. When Checkstyle fails:

1. Read the file, line number, and rule from the build log.
2. Fix the source to match the style of the surrounding code. Do not relax the
   build or skip the check.
3. Re-run the same focused `mvn ... test` command to confirm the fix.

For IDE formatting, import `eclipse/install/Strata-Eclipse-Formatter-Java.xml`
as described in `eclipse/README.md`.

## Joda-Beans validation

The `joda-beans-maven-plugin` runs at the `validate` phase with `stopOnError=true`
and checks that bean classes match what the Joda-Beans generator would produce.
A hand-edited generated section fails the build. Regenerate instead of editing
inside the autogenerated markers. The Scala beans in `collect` and `basics` are
hand-ported from the generated Java and are not checked by this plugin; keep
their property order, meta-bean hash switches and builders exactly in line with
the Java originals.

## Running an example

Examples are self-contained and use bundled sample market data:

```sh
mvn -f examples/pom.xml org.codehaus.mojo:exec-maven-plugin:3.1.0:java -Dexec.mainClass=com.opengamma.strata.examples.FxPricingExample
```

## Test stack

Tests use JUnit 5 (Jupiter, including `@ParameterizedTest`) with AssertJ
assertions, plus `com.opengamma.strata.collect.TestHelper` helpers such as
`assertSerialization`, `assertJodaConvert`, `date`, and `list`. See the
`code-conventions` skill for how tests are structured.
