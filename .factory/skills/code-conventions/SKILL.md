# Strata code conventions

Java production code must compile against Java 8 (no post-8 APIs) and pass the
Checkstyle and Joda-Beans checks that run during the build (see the
`build-and-test` skill). The `collect` and `basics` modules are Scala 3.9.0
(under `src/main/scala`); changes there must keep their Java-facing API and
Joda-Beans behavior unchanged, and their tests stay in Java. The reference
paths below for `basics` types point at the Scala sources (for example
`CurrencyAmount.scala`). When adding or changing code, follow the patterns below
and match the style of the neighbouring code.

## Pattern 1: plain immutable value class

Reference implementation: `CurrencyAmount` in
`modules/basics/src/main/scala/com/opengamma/strata/basics/currency/` (Scala;
Java modules follow the same shape in Java).

- `public final class` with every field `private final`.
- `implements Serializable` with `private static final long serialVersionUID = 1L;`.
- Static factory methods instead of public constructors, usually `of(...)`.
  Add `parse(String)` annotated with Joda-Convert `@FromString` plus a matching
  `@ToString` when the type has a round-trippable string form.
- Private constructor; factories validate and construct.
- No mutators. Operations return new instances.
- `compareTo` via Guava `ComparisonChain`; hand-written `equals` and `hashCode`.
- Class Javadoc explains the design, separates paragraphs with `<p>`, and ends
  with a line such as "This class is immutable and thread-safe."

## Pattern 2: Joda-Beans light immutable bean

Reference implementation: `QuoteId` in
`modules/market/src/main/java/com/opengamma/strata/market/observable/`.

Use this pattern for types that benefit from bean metadata, such as builders and
property access.

- Annotate the class `@BeanDefinition(style = "light", cacheHashCode = true)` and
  implement `ImmutableBean`.
- Declare fields as
  `@PropertyDefinition(validate = "notNull", overrideGet = true) private final ...`.
- Joda-Beans generates getters, builders, the meta-bean, and `equals`/`hashCode`
  between `AUTOGENERATED START` and `AUTOGENERATED END` markers. Never edit code
  inside those markers; the `joda-beans-maven-plugin` validate goal fails the
  build if the generated source does not match.

## Style

- Two-space indentation; no tabs.
- Separate logical sections with a line of dashes, for example
  `//-------------------------------------------------------------------------`.
- Import ordering is enforced by Checkstyle; when adding imports, match the
  grouping used in an existing file rather than guessing.
- Every public class and public method has Javadoc; match the density and
  wording of nearby types.

## Argument validation

- Validate public method arguments with `com.opengamma.strata.collect.ArgChecker`:
  `notNull`, `notEmpty`, `notBlank`, `notNegative`, `notNegativeOrZero`, `isTrue`.
- Document the thrown `IllegalArgumentException` in the factory method Javadoc.

## Tests

- One test class per production class, same package, under `src/test/java`
  (for example `CurrencyAmount` -> `CurrencyAmountTest`).
- JUnit 5 Jupiter: `@Test`, plus `@ParameterizedTest` with a `MethodSource` for
  case tables.
- AssertJ assertions: `assertThat(...)`, `assertThatIllegalArgumentException()`.
- Use `com.opengamma.strata.collect.TestHelper`:
  - `assertSerialization(instance)` checks the serialization round trip.
  - `assertJodaConvert(Class, instance)` checks the `@FromString`/`@ToString`
    round trip.
  - `date(year, month, day)` and `list(...)` build compact test fixtures.

## Public API discipline

- The public API is maintained with backwards compatibility in mind. New public
  types and methods need full Javadoc and should fit the existing naming style.
- Internal `impl` packages are excluded from that promise. For example,
  `com.opengamma.strata.pricer.impl` documents that code in the package and
  subpackages may change in a non-backwards compatible way. Do not expose `impl`
  classes through the API of another module.
